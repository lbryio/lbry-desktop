# Go core: JSON-RPC shim (#681, part of #689)

The first step of the Go core is a process on `localhost:5279` that speaks the same JSON-RPC the app
already sends to `lbrynet`, and forwards everything to `lbrynet` until a method is reimplemented.

- **[rpc-methods.md](rpc-methods.md):** the methods the UI calls (53 today), generated by
  `node scripts/audit-rpc-methods.js`. Re-run it when a call site is added or removed.

## What the shim has to match on the wire

All of this comes from `ui/lbry.ts` (`apiCall`).

- **Transport:** HTTP `POST` to `http://localhost:5279`, with the method name repeated in the query string
  (`?m=<method>`). The shim should accept the query string; the body is what carries the call.
- **Request body:** JSON-RPC 2.0, `{ "jsonrpc": "2.0", "method", "params", "id" }`, where `id` is a
  millisecond timestamp, so it is not unique per call.
- **Request headers:** `Content-Type: application/json-rpc`. The app adds `X-Lbry-Auth-Token` after
  sign-in (`Lbry.setApiHeader`, `ui/store.ts`). The Electron main process also strips `Origin` from
  these POSTs (`electron/index.ts`), so the daemon never sees one.
- **Success:** `response.result`.
- **Errors:** the app rejects when `response.error` is set **or** when `response.result.error` is set,
  so a method can fail with HTTP 200 and an error inside `result`. The shim must pass both shapes through
  unchanged. `response.error` may be an object (`{ message }`) or a plain string.
- **`publish`** has an override hook (`Lbry.overrides.publish`) that can replace the call entirely.

## What this does not cover yet

The audit lists method **names**. Parameter and response shapes are not documented by hand: the plan in
#681 is to record them from real `lbrynet` responses as contract tests, which is more reliable than
reading the call sites.

## Method notes

- `comment_*` have wrappers in `ui/lbry.ts` but no call site. Comments go to their own server through
  `ui/comments.ts`, not the daemon.
- `Lbry[method](...)` in `ui/redux/actions/claims.ts` picks `support_abandon`, `channel_abandon` or
  `stream_abandon` at run time. The script accounts for that case; any new dynamic call needs the same.
